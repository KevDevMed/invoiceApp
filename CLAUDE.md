Guidance for Claude Code working in this repo. Read alongside:

- **`README.md`** — architecture, the frozen IPC contract, money-as-integers,
  the two-ABI native build, the browser preview. Not repeated here.
- **`AGENTS.md`** — the Astryx design-system rules. Everything between the
  `<!-- ASTRYX:START -->` / `<!-- ASTRYX:END -->` markers is generated by
  `npx astryx`; edit around it, never inside it.

This file holds what those two do not: the release mechanics, and the traps that
have already cost real debugging time.

## Environment

- Node 22 (what CI runs). `engines` allows >=20.19; below that `npm ci` refuses.
- A C++ toolchain is required — `better-sqlite3` is a native addon compiled
  twice by `postinstall`, once per ABI.
- Nothing else is needed to develop. There are no `.env` files, no downloaded
  model weights in the repo, and every build secret lives in GitHub Actions.

## Pushing to main cuts a release — read this before merging

`.github/workflows/release.yml` runs on **push to main**. It derives a semver
bump from the conventional-commit subjects since the last `v*` tag
(`scripts/resolve-release-bump.ts`), bumps `package.json`, commits, tags, and
dispatches `build-mac.yml` — which signs and notarises **two** macOS
architectures. Apple's notary queue has taken **30 to 147+ minutes** on
identical inputs, so a release is expensive and cannot be recalled.

Which merges spend one:

| Commit types in the range | Result |
| --- | --- |
| `feat` | minor |
| `fix`, `perf`, anything else parseable | patch |
| `docs` `chore` `ci` `test` `style` `build` only | **none** — run ends green, nothing pushed |
| any breaking marker (`type!:` or a real `BREAKING CHANGE:` footer) | minor while major is 0 |
| any commit carrying `[skip release]` | that commit contributes nothing |

Precedence: breaking beats the non-contributing list; `[skip release]` beats
everything including breaking.

`[skip release]` is recognised in exactly two places — anywhere in the **subject
line**, or on a **body line that contains nothing else** (an optional `-`/`*`/`+`
bullet and one trailing `.,;:!` allowed). Mentioned in prose, backticked,
fenced, or blockquoted, it does **not** opt out. That is deliberate: a false
opt-out would be a release you asked for that silently never happens.

The rules are judged **per commit over the whole range**, not on the head
commit. A `[skip release]` merge landing on top of an unreleased `feat` still
releases the feat.

`workflow_dispatch` remains the way to cut an explicit version, a pre-release,
or 1.0.0.

## Releases are signed and notarised

All five signing secrets (`MAC_CERT_P12`, `MAC_CERT_PASSWORD`, `APPLE_ID`,
`APPLE_APP_PASSWORD`, `APPLE_TEAM_ID`) are set, so `build-mac.yml` runs in
**certificate mode**: real Developer ID signing, hardened runtime, notarised and
stapled. Forks with no `MAC_CERT_P12` fall back to ad-hoc mode automatically.

If a shipped `.dmg` is reported as "damaged", that means **no signature at all**
— check the outer `_CodeSignature` seal, not quarantine flags.

Runner labels are pinned (`macos-15` = arm64, `macos-15-intel` = x64) on
purpose; each arch must build natively because `node-llama-cpp`'s backends are
`cpu`-gated optional dependencies.

## Working across machines

`git fetch origin && git rebase origin/main` before branching. A branch cut from
a stale main produces a PR that conflicts, and **a conflicting PR runs no CI at
all** — it looks unreviewed rather than broken.

## Traps that have already cost time

**Astryx `usePopover` always traps focus.** It calls `useFocusTrap`
unconditionally; `isModal: false` only sets `aria-modal` and does not release
the trap, so the ARIA claims the app is reachable while Tab physically cannot
leave. For a *persistent, non-modal* floating surface use `useLayer`
(`mode: 'context'`, `lightDismiss: false`) and supply `role`, accessible name,
scoped Escape, focus-in and guarded focus-return yourself.
`src/renderer/ui/AssistantDock.tsx` is the worked example.

**Astryx `SideNav` persists collapse twice.** Controlled
`collapsible={{isCollapsed}}` and `resizable={{autoSaveId}}` store separately and
disagree on the next mount — a collapsed-then-relaunched app renders expanded
content into a width-0 box. Seed the controlled state from the same
`localStorage` byte the hook reads, and degrade missing/malformed storage to
expanded. Invisible to typecheck, lint and the whole test suite.

**`border-beam`'s `pulse-outside` overflows its container.** It is the only
preset with negative insets (`-30px` bloom). Near a container edge it gave every
route a horizontal scrollbar. `src/renderer/ui/beam/presets.ts` now asserts no
preset uses it. Tell: a container overflowing by a *constant* amount independent
of viewport width is one absolutely-positioned decorative child, not a layout
bug — fix the preset, don't clip the blur.

**`HashRouter` here is not a data router.** Every location reports
`key: "default"`, and `Router` memoises the location object by field, so a
`history.back()` in the same task as a `navigate()` hands back the *identical*
object and no consumer re-renders. Location object **identity** is the only
in-React signal, and it is blind to the ends-where-it-began case; that one needs
a DOM `hashchange` listener (`pushState` does not fire it). Instrument and read
actual renders before keying anything off route changes.

**`routes.tsx` is frozen.** Build a feature by replacing the body of its barrel
at `src/renderer/features/<feature>/index.tsx`, keeping the exported component
name. Nested routes live inside the barrel. Do not edit the route table.

## Conventions the test setup forces

**There is no DOM harness.** Root `vitest.config.ts` is `environment: 'node'` and
includes only `src/**/__tests__/**/*.test.ts` and `scripts/**/__tests__/**`.
React components are never mounted, so *any logic worth testing must be
extracted into a plain `.ts` sibling* — `filters.ts`, `editorLines.ts`,
`invoiceTabsState.ts`, `chrome.ts`, `pagination.ts` all exist for that reason.
Put decisions in a pure function next to the component, not inside it. Tests go
in a `__tests__/` folder beside the code as `<subject>.test.ts`; `*.smoke.test.ts`
is the opt-in-slow variant. `preview/` has its own vitest project (it runs under
Vite so `?raw` SQL imports resolve).

**No state library.** No redux/zustand/jotai/tanstack — local hooks per feature,
custom hooks for the async ones, context only for theme mode. Data comes
straight from `window.api.invoke`. Do not introduce one without asking.

**`src/domain/` is process-agnostic.** Repositories and queries there take an
explicit `Db` argument, which is what lets Electron and the browser preview share
them. Nothing in `src/domain/` may import from `src/main/`.

Also frozen, beyond `routes.tsx`: the channel list in `src/shared/ipc-contract.ts`,
shipped migrations under `src/db/migrations/`, and the root vitest/tsconfig
project wiring.

## Driving the browser preview

- The app is at **`/app`**. `/` is the marketing landing page — a driver pointed
  at `/` screenshots the wrong thing and every shell assertion fails for the
  wrong reason.
- **Faking macOS does not survive `addInitScript`.** `preview/web-shim.ts`
  `installDesktop()` runs on module import and overwrites `window.desktop` with
  a non-writable `platform: 'web'`. An override must trap `Object.defineProperty`
  itself, and you must read `window.desktop` back in the page before trusting a
  measurement.
- **Port 4300 collides silently.** `preview/server.ts` does not fail loudly:
  a second server dies with `EADDRINUSE` into its log while `curl` still answers
  200 from the *old* one, and the harness then measures a stale build. Confirm
  the listener is yours (`ss -ltnp | grep 4300`, match the pid) before trusting a
  `screenshots.mjs` run. Use `PREVIEW_PORT` + `PREVIEW_ORIGIN` for an isolated
  build.
- **Appearance persists in `preview-data/preview.db`**, not browser storage, so
  it survives a fresh Playwright context and leaks between harness runs. Suites
  that hard-code a control name like `Switch to dark theme` require Light.
  `preview/screenshots.mjs` ends by setting Light, so running it last is a safe
  reset.
- `PREVIEW_RESET=1` for exactly one boot wipes and reseeds. `seedOnBoot` only
  seeds an *empty* database, so a stale seed survives a rebuild and makes
  pagination and filters look broken.

## Deploys

The live browser preview is a Dokploy app that builds `Dockerfile` from `main`
and auto-deploys on every push — no commit-type filter, unlike releases. It
needs a **rebuild**, not a restart: `preview/dist` is baked at image build time.
To tell what is actually deployed, compare the served `assets/index-*.js` hash
against a local `npm run preview:build`; the CSS hash comes from Astryx and
rarely changes, so it is not a signal.
